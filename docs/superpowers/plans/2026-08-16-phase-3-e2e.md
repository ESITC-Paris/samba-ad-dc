# Phase 3 — E2E Suite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax.

**Goal:** `go test ./...` under `test/e2e/` executes the complete B.5
matrix (nominal, operational, negative) against the built image, under
read-only rootfs + minimal capability configuration, locally (arm64) and
in CI (both arches); plus the capability-bisection tooling and the
bidirectional traceability map.

**Architecture:** A separate Go test module `test/e2e` drives the
`docker` CLI through a small harness package (no Docker SDK dependency —
the CLI is the stable, CI-present interface). Protocol assertions run
from a dedicated **test-client image** (Debian trixie-slim +
heimdal-clients, smbclient, ldap-utils, bind9-dnsutils, chrony) so
Kerberos/SMB/LDAP/DNS/NTP are exercised over the network exactly as a
real member would, not via in-container shortcuts. DC containers always
run with `--read-only`, tmpfs `/run` `/tmp`, `cap_drop ALL` + the
capability set from the adaptation profile (§5.6/B.2 proven on every
run). Test function names are the stable traceability IDs (§10.6).

**Tech Stack:** Go ≥1.24 test module, `github.com/go-ldap/ldap/v3`
(LDAPS checks from the harness where a raw client is clearer), docker
CLI, docker compose files under `test/compose/`, test-client image under
`test/client/`.

**Spec:** `SPEC.md` §§5.2, 5.6, 8.2, 8.3, B.5. Roadmap Phase 3.
Entrypoint contract: `docs/adaptation-profile.md` (exit codes 10/11/20/
21/22/23/30; modes auto/provision/join/run/maintenance).

## Global Constraints

- Every B.5 matrix row has exactly one test function; names are
  traceability IDs and MUST NOT be renamed once `docs/traceability.md`
  references them.
- All DC containers: `--read-only`, `--tmpfs /run --tmpfs /tmp`,
  `--cap-drop ALL` + `SYS_ADMIN,NET_BIND_SERVICE,CHOWN,FOWNER,
  DAC_OVERRIDE,SETUID,SETGID` (hypothesis set; Task 6 bisects), never
  `--privileged` (§5.2).
- A mere container start is not a test (§8.2): every test asserts
  protocol-level behavior or exact exit codes + message content.
- Negative tests assert BOTH the documented exit code AND that stderr
  contains the documented cause+remedy marker (§6.5).
- Two-DC tests verify replication BOTH directions by object propagation
  (B.5).
- Test secrets are throwaway literals, clearly marked; no secret
  reaches an env var of the DC container (`*_FILE` only, §6.1).
- Upgrade test auto-skips (with an explicit skip reason) while no
  published tag exists (§8.3 first-release rule).
- Commit trailers as in Phase 2 plan.
- Timeouts: provision ≤ 5 min, join ≤ 5 min, health-transition ≤ 3 min
  — generous for QEMU-free CI runners; fail with container logs dumped.

### Task 1: Harness + test-client image

**Files:**
- Create: `test/e2e/go.mod` (module
  `github.com/esitc-paris/samba-ad-dc/test/e2e`),
  `test/e2e/harness/harness.go`, `test/e2e/harness/client.go`,
  `test/client/Dockerfile`, `test/e2e/main_test.go`

**Interfaces (produced, used by every later task):**
```go
package harness
// Image() returns the DC image under test: env E2E_IMAGE or "samba-ad-dc:dev".
// ClientImage() builds (once, sync.Once) and returns the test-client image.
func Image() string
func ClientImage(t *testing.T) string
type DC struct { Name, IP, Realm string /* ... */ }
// StartDC runs the DC image with the constrained profile (read-only,
// tmpfs, cap set), fresh named volumes, on network net, mode + env.
// Registers t.Cleanup for container+volume removal. Returns after
// container start (not after health) — use WaitHealthy.
func StartDC(t *testing.T, net, name, mode string, env map[string]string, opts ...Opt) *DC
func WaitHealthy(t *testing.T, name string, within time.Duration)
// RunDCExpectExit runs the DC image in the SAME constrained profile,
// waits for exit, returns (exitCode, combined logs).
func RunDCExpectExit(t *testing.T, net, name, mode string, env map[string]string, opts ...Opt) (int, string)
// Client executes cmd in a one-off test-client container on net and
// returns combined output; non-zero exit -> t.Fatal with output unless
// wantErr.
func Client(t *testing.T, net string, env map[string]string, cmd ...string) string
func ClientErr(t *testing.T, net string, env map[string]string, cmd ...string) (int, string)
// Network creates a user-defined bridge with a /24 and returns its
// name; cleanup registered. (CI-only topology: production docs mandate
// macvlan/host — a user-defined bridge between containers has no NAT
// between the members and the DC, which is what B.3 actually forbids.)
func Network(t *testing.T) string
// Secret writes value to a temp file and returns a bind-mount spec.
func Secret(t *testing.T, value string) (hostPath string)
```
- `test/client/Dockerfile`: `FROM debian:trixie-slim@<same digest as
  versions.yaml runtime>` + `apt-get install --no-install-recommends
  heimdal-clients smbclient ldap-utils bind9-dnsutils chrony
  ca-certificates` (justified: protocol clients for E2E only; NOT a
  published image — §5.1 scope is published images).
- `main_test.go`: `TestMain` asserts docker present, image exists
  (else fails with "build the image first: docker build -t
  samba-ad-dc:dev .").
- Realm under test: `AD.E2E.TEST`, domain `E2E`, password
  `E2ePassw0rd!` (throwaway, in-repo constant with a comment).

Steps: write harness + a smoke test `TestHarnessSmoke` (starts DC in
provision mode, waits healthy, stops) → `go test ./... -run
TestHarnessSmoke -v` green → gofmt/vet → commit
`feat(e2e): container harness and protocol test-client image`.

### Task 2: Nominal single-DC matrix

**Files:**
- Create: `test/e2e/nominal_test.go`

One package-level fixture (in `nominal_test.go`): a shared provisioned
DC started once per package run (sync.Once via TestMain or explicit
fixture test ordering is forbidden — use a getter `provisionedDC(t)`
with sync.Once) — read-only tests share it; each mutating test gets its
own.

Test functions (IDs frozen):
- `TestProvision`: fixture DC reaches healthy; `docker logs` contains
  the provision completion; `samba-tool domain level show` via
  `docker exec` reports the realm. (exec of samba's own CLI allowed.)
- `TestDNSSRVRecords`: from client: `dig +short SRV
  _ldap._tcp.ad.e2e.test @<dc-ip>` returns the DC; same for
  `_kerberos._udp`.
- `TestKerberosKinit`: client: `printf %s "$PW" | kinit
  Administrator@AD.E2E.TEST` succeeds; `klist` shows the TGT.
- `TestKerberizedSMB`: client: after kinit, `smbclient -k
  //dc1.ad.e2e.test/netlogon -c ls` succeeds (uses the ticket).
- `TestNTLMAuth`: client: `smbclient //dc1.ad.e2e.test/netlogon -U
  'E2E\Administrator%<pw>' -c ls` with Kerberos disabled
  (`--use-kerberos=off`) succeeds.
- `TestLDAPSCertificate`: harness go-ldap: TLS dial `ldaps://<ip>:636`
  with `InsecureSkipVerify` OFF but custom RootCAs read from the DC's
  generated CA (`docker cp` `/var/lib/samba/private/tls/ca.pem`) →
  rootDSE search succeeds; assert cert CN matches hostname.
- `TestSignedNTPWiring`: `docker exec` DC: socket
  `/var/lib/samba/ntp_signd/socket` exists; from client: `chronyd -Q
  'server <dc-ip> iburst'` one-shot query answers (plain NTP served);
  smb.conf contains `ntp signd socket directory` wiring.
- `TestDBConsistency`: `docker exec` DC `samba-tool dbcheck` → "0
  errors"; plus one-off maintenance-mode container on a COPY of the
  fixture volumes? No — maintenance on the live fixture volume while
  samba runs is unsafe; instead: dedicated DC provisioned fresh,
  stopped, re-run with SAMBA_MODE=maintenance → exit 0 and "0 errors"
  in logs. (Also covers the maintenance nominal mode of B.4.)

Steps: write tests (they fail: missing fixture pieces) → implement
fixture helpers → all green locally → commit
`test(e2e): nominal single-DC matrix (Kerberos, NTLM, DNS, LDAPS, NTP, dbcheck)`.

### Task 3: Join + bidirectional replication

**Files:**
- Create: `test/e2e/replication_test.go`, `test/compose/two-dc.yaml`

- `test/compose/two-dc.yaml`: network `adnet` (bridge, static IPs
  172.28.0.0/24), `dc1` (provision), `dc2` (join, `SAMBA_JOIN_*`,
  DNS pointed at dc1 via `dns:` key), both with the full constrained
  profile (read_only, tmpfs, cap_drop/cap_add, volumes). Used by

  e2e-repl up -d` from the harness.
- `TestJoinReplicationBothWays`:
  1. compose up; both healthy (dc2's join completes).
  2. `docker exec dc1 samba-tool user create alice ...` → poll (≤120 s)
     `docker exec dc2 samba-tool user show alice` succeeds.
  3. `docker exec dc2 samba-tool user create bob ...` → poll dc1 shows
     bob.
  4. `docker exec dc1 samba-tool drs showrepl` contains no failures
     ("consecutive failures: 0" for each partner or equivalent).
  5. compose down -v via t.Cleanup.

Commit `test(e2e): additional-DC join with bidirectional replication`.

### Task 4: Operational matrix (restart, backup/restore, upgrade, downgrade)

**Files:**
- Create: `test/e2e/operational_test.go`

- `TestIdempotentRestart`: provision DC (own volumes); create user
  `carol`; `docker stop -t 12` (assert exit 0 of the container — clean
  SIGTERM shutdown §6.3); start a NEW container in `run` mode on the
  SAME volumes → healthy; `carol` still present; marker unchanged
  (version identical, no re-init in logs).
- `TestOfflineBackupRestore`: provision DC; create user `dave`; stop
  DC. Run one-off container (same image, volumes RO where possible):
  `docker run --rm --entrypoint samba-tool -v vols... -v backupvol:/backup
  <img> domain backup offline --targetdir=/backup/bk` → tarball exists.
  Restore: fresh volumes, one-off `--entrypoint samba-tool ... domain
  backup restore --backup-file=... --targetdir=/var/lib/samba`? —
  ACTUALLY: restore writes a ready state tree; then start `run`-mode DC
  on the restored volumes → healthy; `dave` exists (object-level
  verification, B.5). The exact samba-tool restore invocation is the
  implementer's to get right from `samba-tool domain backup restore
  --help`; the ASSERTIONS above are binding.
- `TestUpgradeFromLastPublished`: if env `E2E_UPGRADE_FROM` (an image
  ref) is empty → `t.Skip("first release of branch: no published tag
  yet (SPEC §8.3)")`. Else: provision with the OLD image, create user,
  stop; start CANDIDATE image in `run` mode on same volumes → healthy,
  dbcheck-on-upgrade visible in logs, user intact, marker bumped.
- `TestDowngradeRefused`: provision with candidate image, stop; edit
  marker in the volume to a higher version (`docker run --rm -v vol:/v
  debian... sed/jq` — or a helper writing marker JSON with version
  99.0.0); start `run` mode → exit 22, stderr names both versions and
  the remedy.

Commit `test(e2e): operational matrix (restart, offline backup/restore, upgrade, downgrade guard)`.

### Task 5: Negative matrix

**Files:**
- Create: `test/e2e/negative_test.go`

- `TestMissingSecretFailsFast`: provision mode, no
  `SAMBA_ADMIN_PASSWORD_FILE` → exit 10, stderr names the variable;
  variant: variable points at nonexistent file → exit 11, stderr names
  the path and remedy. Both within 30 s (fail-fast).
- `TestPlainEnvSecretRejected`: `SAMBA_ADMIN_PASSWORD=x` set → exit
  10, stderr instructs `_FILE` convention (§6.1 MUST NOT support).
- `TestProvisionOverStateRefused`: provision DC, stop; re-run
  provision mode on same volumes → exit 20; state untouched (restart in
  run mode still healthy — proves refusal really protected state).
- `TestRunModeWithoutStateRefused`: run mode, fresh volumes → exit 21,
  stderr mentions volume remedy.

Commit `test(e2e): negative matrix (secret handling, state-overwrite and missing-state refusals)`.

### Task 6: Capability bisection tooling

**Files:**
- Create: `test/capbisect/bisect.sh`, `.github/workflows/capbisect.yml`

- `bisect.sh`: for each cap C in the hypothesis set, run the harness
  smoke subset (`go test ./test/e2e/ -run
  'TestProvision$|TestKerberosKinit|TestIdempotentRestart' `) with
  `E2E_CAPS` env minus C (harness reads `E2E_CAPS` override); emit a
  table `cap -> required|droppable`; also try adding none beyond the
  set (baseline già). Also test candidate DAC_READ_SEARCH need per B.2.
  Output: `capbisect-report.txt`.
- Harness change (small, Task 6 owns it): `StartDC` reads `E2E_CAPS`
  (comma list) when set.
- `capbisect.yml`: `workflow_dispatch` only; runs bisect.sh on both
  runner arches; uploads report artifact. Findings are applied to
  `docs/adaptation-profile.md` (capability set "established by CI
  bisection on <date>, workflow run <id>") by a PR — this task runs the
  LOCAL bisection now and updates the profile with local arm64 results
  marked "local pending CI confirmation".

Commit `test: capability bisection driver and workflow; record locally established set`.
