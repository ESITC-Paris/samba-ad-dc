# Runtime package manifest — SPEC §5.1 ("every installed package MUST be
# justifiable; if nobody knows why it is there, it goes").
#
# Format: one `package  # why` line. Comments and blank lines are ignored;
# the Dockerfile feeds this file to apt-get after stripping `#...`.
#
# The library half of this list is DERIVED, not guessed: it is the output
# of scripts/derive-runtime-packages.sh run against the builder's DESTDIR
# (ldd closure of every ELF object, minus what the DESTDIR itself ships,
# mapped to owning packages by dpkg -S). The justifications name the
# actual linkage, obtained from DT_NEEDED entries — "linked by X" means a
# Samba object lists that soname directly, "pulled in by X" means the
# library is only reached through X.
#
# Transitive libraries are listed explicitly rather than left to apt on
# purpose: SPEC §9bis.1.c has the watcher monitor the distribution package
# index "restricted to each image's runtime package list", so anything not
# named here would never trigger a security rebuild.
#
# What this method cannot see, and what is therefore justified by hand at
# the bottom: interpreted (python) dependencies and service-level needs.
#
# scripts/check-image-packages.sh proves the converse property: the final
# image contains nothing beyond the base image plus the apt closure of
# this file.
